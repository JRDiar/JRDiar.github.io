Implementation Plan - WAITING_REBOTE Logic
Goal Description
Implement a "WAITING_REBOTE" (Waiting for Rebound) logic to replace the current "Hard Block" when 5M momentum contradicts the main direction. Instead of instantly rejecting the trade, the bot will now analyze if there is sufficient underlying market force to justify waiting for a rebound. If confirmed, this state is propagated by the orchestrator.

User Review Required
IMPORTANT

This change introduces a new return state WAITING_REBOTE which propagates specific configuration for the "Sniper" or execution engine to monitor the asset. Correction: The NO_OPERAR case has been strictly defined to maintain compatibility with existing consumers (singular reason field).

Proposed Changes
Logic Comparison
Feature	Current Logic	New Logic
Momentum Conflict	Returns WAIT (Block)	Returns WAITING_REBOTE (if Force > 25 & Pattern > 70)
Orchestrator	Returns OPERAR/NO_OPERAR	Adds return case for WAITING_REBOTE
NO_OPERAR Schema	Incomplete in previous draft	Fully compatible (confidence, reason, full_analysis)
