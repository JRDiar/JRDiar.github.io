## 🎯 VISIÓN GENERAL

### Concepto del Bot

BrainTrader es un sistema de trading automatizado que **simula el proceso de toma de decisiones de un trader humano experto**, utilizando una arquitectura de capas inspirada en el cerebro humano. El bot no es un simple ejecutor de señales técnicas, sino un **sistema inteligente anticipatorio** que:

- **Percibe** el mercado a través de múltiples temporalidades
- **Analiza** contexto completo antes de decidir
- **Decide** inteligentemente basándose en consenso multi-timeframe
- **Ejecuta** con precisión matemática
- **Gestiona** trades con inteligencia adaptativa
- **Aprende** de sus operaciones (re-análisis de breakevens)

### Filosofía Central

```
🧠 HUMANO → BOT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Trader ve gráficos → Bot analiza 5 timeframes
Trader evalúa fuerza → Bot calcula ADX + Momentum
Trader proyecta timing → Bot usa física (v + a)
Trader decide operar → Bot requiere consenso 4+/6 TFs
Trader gestiona salida → Bot usa 5 señales inteligentes
Trader re-evalúa → Bot re-analiza breakevens
```

## 🧠 SISTEMA DE DOS HEMISFERIOS

### Concepto

El módulo de ejecución fue dividido en **dos hemisferios** (inspirado en el cerebro humano), cada uno con funciones especializadas:

```
┌─────────────────────────────────────────────────────────────┐
│                    BRAIN EXECUTOR                            │
│                 (Mente del Trader)                           │
└─────────────────────────────────────────────────────────────┘
                            │
            ┌───────────────┴───────────────┐
            ▼                               ▼
┌──────────────────────┐        ┌──────────────────────┐
│  HEMISFERIO IZQUIERDO │        │  HEMISFERIO DERECHO   │
│  (Entrada \u0026 Triggers) │        │  (Monitoreo \u0026 Salida) │
├──────────────────────┤        ├──────────────────────┤
│ brain_executor_      │        │ brain_executor.py     │
│   entry.py           │        │                       │
│                      │        │                       │
│ RESPONSABILIDADES:   │        │ RESPONSABILIDADES:    │
│ • Verificar triggers │        │ • Monitorear trades   │
│ • ADX + Momentum     │        │ • Gestión PnL         │
│ • Validar volumen    │        │ • Breakeven           │
│ • Bypass inteligente │        │ • Trailing stop       │
│ • Decidir ENTRADA    │        │ • 5 señales de salida │
│                      │        │ • Stop loss thread    │
└──────────────────────┘        └──────────────────────┘
       (Analítico)                    (Emocional)
```

### Hemisferio Izquierdo: Entrada y Triggers
**Archivo:** `brain_executor_entry.py`

**Función principal:** `check_trigger_activated_intelligent(symbol, watchlist_data)`

**Responsabilidades:**
**Responsabilidades:**
1. **Validación de triggers (Sistema de Puntuación / Fuzzy Logic):**
   - **Concepto:** En lugar de rechazar por una sola condición fallida, se suman puntos.
   - **Cálculo de Score:**
     - **ADX:** +1 punto por cada unidad sobre 20 (Max 40).
     - **Momentum:** +5 puntos por cada vela consecutiva (Max 20).
     - **Volumen:** +20 (>1.5x), +10 (>1.0x), -10 (<0.6x).
     - **Spread DI:** +10 si hay claridad (>5).
     - **Explosión:** +50 puntos (Override automático).
   - **Decisión:**
     - Si **Score Total ≥ 60** → **ENTRADA APROBADA**.
   - *Beneficio:* Un ADX muy fuerte puede compensar un volumen ligeramente bajo.

2. **Validación de dirección:**
   - Verifica DI+ vs DI- en 15M
   - Confirma momentum alineado
   - Detecta cambios de tendencia
   - *Nota:* Esta es la única regla estricta (no negociable).

**Retorna:**
```python
{
    'activated': True/False,
    'adx': 28.5,
    'momentum_age': 5,
    'volume_ratio': 2.15,
    'is_explosive': True/False
}
```

### Hemisferio Derecho: Monitoreo y Salida
**Archivo:** `brain_executor.py`

**Clase principal:** `TradeManager`

**Responsabilidades:**
1. **Gestión de capital:**
   - Capital disponible
   - División por trade
   - Max trades simultáneos

2. **Entrada a trade:**
   - `enter_trade(symbol, watchlist_data)`
   - Registro en DB
   - Notificación Telegram
   - Escritura a Google Sheets

3. **Monitoreo activo:**
   - `monitor_active_trades()`
   - Tracking de PnL en tiempo real
   - Verificación de breakeven (+2%)
   - Detección de stop loss

4. **Salida inteligente:**
   - `check_exit_signals()` → 5 señales:
     1. 📉 **Desaceleración:** Velas \u003c70% promedio
     2. 📊 **Volumen bajo:** \u003c60% promedio
     3. ⚠️ **Divergencia:** Precio vs Momentum
     4. 🎯 **Zona crítica:** \u003c1% del target
     5. 🛡️ **Buffett:** Pérdida \u003e2% en \u003c10min

5. **Cierre de trade:**
   - `close_trade(symbol, reason)`
   - Registro de resultado
   - Actualización capital
   - Historial

6. **Re-análisis:**
   - `reanalyze_breakeven_exits()`
   - Espera 5 minutos después de breakeven
   - Re-analiza moneda completamente
   - Puede re-entrar si setup mejoró

### Ventajas de Dos Hemisferios

✅ **Separación de responsabilidades:**
- Entrada = Analítico, preciso, estricto
- Salida = Adaptativo, protector, inteligente

✅ **Código más mantenible:**
- Cada hemisferio es independiente
- Fácil modificar lógica de entrada sin tocar salida

✅ **Bypass inteligente localizado:**
- Solo afecta la entrada
- No contamina la gestión de trades activos

✅ **Testing más fácil:**
- Se puede probar entrada sin ejecutar trades
- Se puede probar gestión con trades simulados

## 📦 MÓDULOS DEL CEREBRO

### 1. `brain_analyzer.py` - Análisis Cascada
**Líneas:** 840  
**Paradigma:** Análisis secuencial con rechazo temprano

#### Funciones Principales

**`analyze_4h(symbol)`** - Contexto Dominante
- Define clima de mercado (ALCISTA/LATERAL/BAJISTA)
- Calcula ADX, Momentum, EMAs
- **NUNCA rechaza** - Solo informa

**`analyze_1h(symbol)`** - Confirmación Intermedia
- Confirma tendencia 4H
- Detecta edad del momentum
- Valida confluencia

**`analyze_15m(symbol)`** - Timing de Entrada
- Calcula timing proyectado
- Detecta S/R cercanos
- Determina viabilidad operativa

**`analyze_5m(symbol)`** - Ejecución Inmediata
- Velocidad y aceleración actual
- Data para proyección física
- **NUNCA rechaza** - Solo data

**`analyze_1d(symbol)`** - Clima General
- RSI diario
- Tendencia macro
- Velas consecutivas
- Previene operar contra corriente

**`analyze_trend_evolution(symbol)`** - Explosiones 1M
- Analiza velas de 1 minuto
- Detecta tendencias explosivas
- Permite bypass de filtros estrictos
- Retorna `is_explosive` flag

**`analyze_coin_complete(symbol)`** - Orquestador
- Ejecuta análisis completo
- Calcula score 0-100
- Determina viabilidad
- Retorna estructura completa

#### Sistema de Scoring

```python
BASE_SCORE = 50

BONOS (+):
  Confluencia 4H (misma dirección)      +20
  Confluencia 1D (larga alineación)     +15
  EMAs cercanas 4H (\u003c1%)                +10
  EMAs cercanas 15M (\u003c1%)               +10
  Edad joven (\u003c5 velas)                  +15
  Sin obstáculos (\u003e5% a S/R)            +10
  
PENALTIES (-):
  EMAs separadas (\u003e2%)                  -10 (por TF)
  Edad madura (\u003e10 velas)               -10
  Estructura mala (ADX \u003c20)             -20
  
SCORE FINAL = BASE + BONOS - PENALTIES
MÍNIMO VIABLE = 70
```

### 2. `brain_intelligent.py` - Decisión Inteligente
**Líneas:** 267  
**Paradigma:** Análisis paralelo holístico

#### Paradigma Diferente

```
CASCADA (brain_analyzer):        PARALELO (brain_intelligent):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1D → 4H → 1H → 15M → 5M         1D, 4H, 1H, 15M, 5M, 1M
Si 4H falla → RECHAZA           Al mismo tiempo
Análisis binario (SÍ/NO)        ¿Cuántos dicen SÍ?
```

#### Función Principal

**`decide_intelligently(symbol)`**

**Paso 1:** Analiza todas las temporalidades en paralelo
```python
context = {
    '1D': analyze_1d(symbol),
    '4H': analyze_4h(symbol),
    '1H': analyze_1h(symbol),
    '15M': analyze_15m(symbol),
    '5M': analyze_5m(symbol),
    '1M': analyze_trend_evolution(symbol)
}
```

**Paso 2:** Cuenta señales
- `bullish_count`: Temporalidades alcistas
- `strong_count`: ADX \u003e 20
- `explosive_count`: Explosiones en 1M

**Paso 3:** Toma decisión holística

**Reglas de decisión:**
1. **Explosión 1M + 2+ fuertes** → OPERAR (SCALPING)
2. **4+ alcistas + 3+ fuertes** → OPERAR (SWING/POSITION)
3. **5+ alcistas** → OPERAR (SWING) - Consenso masivo
4. **Cualquier otro caso** → NO_OPERAR

**Retorna:**
```python
{
    'action': 'OPERAR' | 'NO_OPERAR',
    'trade_type': 'SCALPING' | 'SWING' | 'POSITION',
    'reason': "Explosión 1M + 3 temporalidades fuertes",
    'confidence': 'BAJA' | 'MEDIA' | 'ALTA' | 'MUY_ALTA',
    'context_summary': "Bullish: 5/6 | Strong: 3/6 | Explosivo: SÍ",
    'full_analysis': {...}  # Para debugging
}
```

#### Ventajas del Modo Inteligente

✅ **Simula pensamiento humano:**
- "Veo que 5 de 6 temporalidades están alcistas"
- "Hay una explosión en 1M"
- "3 temporalidades tienen fuerza real (ADX \u003e 20)"
- **Decisión:** "Opero con confianza ALTA"

✅ **No descarta oportunidades prematuras:**
- Si 4H está lateral pero 1M está explosivo → Puede operar
- Si 1H está débil pero 5 de 6 alcistas → Puede operar

✅ **Más flexible que cascada:**
- Cascada: Binario (pasa 100% o rechaza)
- Inteligente: Gradiente (¿cuántos dicen SÍ?)

def _extract_score(score_value, default=0):
    """Recursively extract integer score from potentially nested dict."""
    if score_value is None:
        return default
    if isinstance(score_value, (int, float)):
        return int(score_value)

## 💡 DECISIONES DE DISEÑO

### 1. ¿Por qué Dos Modos de Análisis?

**Modo CASCADA:**
- Para trading conservador
- Requiere 100% de alineación
- Menos entradas, más precisas

**Modo INTELIGENTE:**
- Para capturar más oportunidades
- Decisión holística
- Más entradas, mayor volumen

**Razón:** Dar flexibilidad al usuario según perfil de riesgo

### 2. ¿Por qué Análisis 1M?

**Problema:** Filtros estrictos pueden perder oportunidades explosivas

**Solución:** 
- Analizar velas de 1 minuto
- Detectar tendencias en formación
- Permitir entrada temprana con bypass

**Tradeoff:**
- ✅ Captura scalping oportunidades
- ⚠️ Mayor riesgo si explosión falla

### 3. ¿Por qué División en Hemisferios?

**Inspiración:** Cerebro humano

**Analogía:**
- Hemisferio Izquierdo = Analítico, lógico, decide entrada
- Hemisferio Derecho = Emocional, protector, gestiona salida

**Beneficio práctico:**
- Código más organizado
- Testing independiente
- Evolución separada

### 4. ¿Por qué Scoring 0-100?

**Alternativa rechazada:** Scoring binario (aprobado/rechazado)

**Ventaja de 0-100:**
- Permite ordenar oportunidades
- Top 20 por score = mejores setups
- Ajuste fino con bonos/penalties
- Fácil interpretación (como examen)

### 5. ¿Por qué Re-análisis de Breakevens?

**Observación:** Monedas salen en breakeven y después explotan

**Razón:**
- Entrada fue temprana (timing incorrecto)
- Pero setup sigue válido

**Solución:**
- Esperar 5 minutos
- Re-analizar moneda
- Si setup mejoró → Re-entrar

**Beneficio:**
- Segunda oportunidad
- No pierde setup válido por timing

### 6. ¿Por qué Google Sheets?

**Alternativas:** SQLite, PostgreSQL, MongoDB

**Ventajas de Sheets:**
- ✅ Acceso remoto desde cualquier dispositivo
- ✅ Visualización inmediata (gráficos, filtros)
- ✅ No requiere servidor
- ✅ Permite colaboración (revisar trades con alguien)
- ✅ Backup automático en la nube

**Desventaja:**
- ⚠️ Latencia en escritura (mitigado con batch writes)

### 7. ¿Por qué Thread Separado para Stop Loss?

**Problema:** Stop loss debe verificarse continuamente (cada 2s)

**Solución:**
- Thread dedicado `monitor_stop_loss_thread()`
- No bloquea loop principal
- Detecta stop loss inmediatamente

**Beneficio:**
- Protección en tiempo real
- No espera siguiente ciclo (60s)
